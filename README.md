# saya_bot

一个在 QQ 群聊中运行的对话机器人。以**个人账号**身份接入（走 NapCat / OneBot v11，不依赖官方机器人开放平台），
对话能力由 **DeepSeek** 提供。机器人本体**零第三方依赖**，只用 Python 标准库。

要验收当前版本，见 [`ACCEPTANCE.md`](ACCEPTANCE.md)（逐条打勾的清单）。

## 概述

| 能力 | 说明 |
|---|---|
| **触发判定** | 每个群单独配置策略：`silent` / `mention` / `keyword` / `random` / `always`。非 `silent` 的群记录全部消息（供记忆与统计），是否回复由策略决定。`keyword` 命中一次之后会跟随该用户接下来的若干条消息，不必每条都带关键词 |
| **对话** | 以固定人格回应，带上下文与记忆；支持中文、日文、英文，跟随对方使用的语言 |
| **身份认知** | 主人 / 管理员 / 熟人的判定只看 QQ 号，判定结果作为**可信信息**进入系统提示，模型因此知道自己在跟谁说话 |
| **多模态** | 识别群里的图片。三条可选路线：主模型直接看图 / 外包给专用 CV 模型出文字 / CV 画编号框后交主模型推理 |
| **记忆** | SQLite 本地存储，分三层：会话消息、话题、成员清单。带容量上限与自动裁剪，注入时只取相关片段 |
| **关系记忆** | 主人与管理员说过的、需要长期记住的事，单独存一份，不参与裁剪；`tools/notes.py` 可查看与删除 |
| **知识源** | 模型可自行调用工具查萌娘百科与本地剧情语料（function calling），用于认梗与考据 |
| **设置管理** | 群策略 / 主人 / 管理员 / 白名单 / 触发参数都可在运行时修改，改完立刻生效。命令语义与前端无关，同一个后端挂着多个前端 |
| **防注入** | 结构性隔离为主：用户产生的文本一律包进边界标记后才进提示词；私聊白名单关掉整块攻击面；另加输入检测与输出过滤 |
| **成本记账** | 每条回复按输入（缓存命中 / 未命中两档）与输出三档计价累计，连同 token、延迟一起写入埋点 |
| **埋点** | 每条消息的处理过程写入 JSONL：触发原因、token、延迟、成本、工具调用、注入命中情况。文件按大小轮转 |

## 使用

### 环境要求

- **Python 3.11+**。机器人本体不需要安装任何第三方包。
- 可选 **NapCat**：接入真实 QQ 时才需要。
- 可选**第二套解释器**：只有视觉的路线 B / C 需要（CV 进程有第三方依赖，与本体隔离）。

### 配置

```bash
cp .env.example .env
```

`.env.example` 里每一项都有注释说明。常用项：

| 键 | 作用 |
|---|---|
| `SAYA_LLM_API_KEY` | 模型密钥。**只放在 `.env`，永不提交** |
| `SAYA_ADAPTER` | `mock`（本地假事件，开发用）或 `onebot11_http`（真实 QQ） |
| `SAYA_OWNER_ID` / `SAYA_ADMIN_IDS` / `SAYA_FRIEND_ALLOWLIST` | 允许私聊机器人的人。**不配置则任何人的私聊都被忽略** |
| `SAYA_GROUP_POLICIES` | 形如 `群号:策略`，逗号分隔；未列出的群走 `SAYA_GROUP_DEFAULT_POLICY` |
| `SAYA_VISION_ROUTE` | `direct` / `delegated` / `hybrid` |
| `SAYA_PRICE_IN` / `SAYA_PRICE_CACHE_HIT` / `SAYA_PRICE_OUT` | 三档价格（元 / 百万 token）。留 0 则埋点里的成本恒为 0 |

### 运行

**推荐入口是根目录的 `saya_bot_controller.bat`**（Windows 双击）。该窗口同时充当监视器与控制器：

```
start / end / restart / status     启停与查看状态
+ 全部设置命令（群策略、主人、管理员、白名单、触发参数）
```

一个窗口开到底，不必每次重开终端。**该窗口退出时机器人一并终止** —— 否则会留下无人接管、还占着端口的实例。

也可以直接用脚本启动（不经控制台）：

```bash
cd project_main
python run.py --check     # 先自检：配置、模型连通性、端口占用
python run.py             # 正式启动
```

`--check` 不连 QQ、不发消息，会**一次性列出所有问题**而不是遇到第一个就退出。

接真实 QQ 时，启动脚本按「确认 QQ 侧存活 → 自检 → 启动」的顺序执行：

```bash
tools/start_saya.bat      # Windows 双击
bash tools/start_saya.sh  # WSL
```

### 改设置的三条路

| 场景 | 怎么做 | 生效时机 |
|---|---|---|
| 机器人**在运行**，要立刻改 | 在 `saya_bot_controller.bat` 那个窗口里输入命令 | 立刻 |
| 不想开控制台 | 在机器人所在的那个终端里输入同样的命令 | 立刻 |
| 机器人**没在运行** | `python tools/config.py <命令>` | 下次启动 |

三条路走的是**同一套命令**（语义在 `project_main/src/saya/manage.py`），不存在"某个前端少一条命令"的情况。

### 测试

```bash
cd project_main && python -m unittest discover -s tests -v
```

全部测试只用标准库，clone 下来即可运行，不需要建虚拟环境。

### 发布前

```bash
python tools/privacy_scan.py
```

它扫描**可能被提交的文件**与**全历史**两处，用于确认没有密钥、群号、邮箱等真值进仓库。
判据是**退出码**，不是输出。

## 实现

### 分层

```
adapter（接入） → core（内核） → services（能力） → obs（埋点）

顶层：config / envfile / manage / console / watchdog / domain
```

依赖单向流动，**换 QQ 后端只改 adapter**。适配器接口是同步的：接入层收事件，
内核逐条处理，任一环节出错只丢当前这条消息，主循环继续。

| 目录 | 职责 |
|---|---|
| `project_main/src/saya/adapter/` | OneBot v11 事件解析、HTTP 接入、Mock 回放 |
| `project_main/src/saya/core/` | 触发判定、身份判定、人格与提示词、防注入护栏、记忆、长期记忆、工具调用、流水线、上下文裁剪、运行时命令台 |
| `project_main/src/saya/services/` | 模型通道与成本核算、视觉、知识源（萌娘百科 / 本地语料）、附属进程、MCP 客户端、DNS 缓存 |
| `project_main/src/saya/obs/` | JSONL 埋点（带轮转） |
| `project_main/src/saya/`（顶层） | 配置加载、`.env` 写入、管理命令语义、控制台编码、看护线程 |
| `project_main/cv_mcp/` | 专用 CV 模型的 MCP server（独立进程，第三方依赖隔离在这里） |
| `project_main/persona/` | 人格正文、角色考据、剧情概览；抓下来的语料另存且不进仓库 |
| `project_main/experiment/` | 对照实验的执行器与测试集构建 |
| `tools/` | 与机器人本体无关的独立脚本：常驻控制台、离线改设置、启动、抓网页、切语料、查看长期记忆、隐私自检 |
| `docs/` | 需求基线、架构与决策记录、路线图、交接页、文风规则 |

### 一条消息的处理过程

```
adapter 收到事件
  → 触发判定（不该观察就到此为止）
  → 写记忆 / 写长期记忆
  → 组装上下文（人格系统提示 + 身份 + 长期记忆 + 记忆片段 + 本条消息）
  → 护栏（用户产生的文本全部包裹成不可信区域）
  → 生成（模型可自行调用工具，结果回灌后再答）
  → 输出过滤
  → 发送
  → 埋点
```

### 设计约束

- **零第三方依赖**是刻意的：clone 下来就能跑，测试不需要环境准备。CV 的依赖被隔离在独立进程里。
- **一切用户产生的文本都是不可信的**，包括群名片、记忆内容、长期记忆、历史消息，
  以及**从图片里读出来的文字**。它们进提示词前必须经过 `guard` 的包裹函数，
  否则就是一条注入通道。唯一可信的是代码生成的结构性标签（如身份判定）。
- **密钥不落盘**：只从环境变量或本地 `.env` 读取，代码、文档、提交历史中都不出现。
- **不做任何对抗性绕过**。最初针对的是 QQ 风控（个人账号接入非官方协议本身有封号风险，知情接受，但不做对抗），
  同样适用于第三方网站的防护措施：不实现验证码 / PoW 求解、不伪造浏览器指纹、不换 IP 规避。
  拿不到的数据**如实留白**。
- **界面文本与开发注记分开写**。屏幕上打出来的字用说明书体：书面、简洁、陈述事实；
  不口语、不拟人、不用「你」。规则见 [`docs/style.md`](docs/style.md)，
  由 [`docs/contract.md`](docs/contract.md) 提炼。
