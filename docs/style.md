# style · 写给使用者的文本怎么说话

> 来源：所有者 2026-10-16 亲手改写的一份对照（[`contract.md`](contract.md)）。
> 他把同一段控制台输出**左右各写了一遍** —— 左边是我的，右边是他要的。
> 这份文件就是把那次的差异**提炼成能照着执行的规则**。
>
> 上游同名文件：`~/.claude/style.md`（跨项目通用，那边只留原则，例子在这边）。

---

## 0. 一句话

**说明书体。** 书面、简洁、陈述事实。
**不口语、不拟人、不用"你"、不解释"为什么"、不打招呼。**

对照一下同一个意思的两种写法：

| ❌ 我写的 | ✅ 他要的 |
|---|---|
| 没在跑。敲 start 起它。 | 未运行。输入 start 启动。 |

前者像**旁边有个人在跟你说话**；后者像**设备面板上的提示**。
**要的是后者。**

---

## 1. 先分清在写哪种文本

⚠️ 这一步不做，后面全白搭 —— 混语域就是这个项目**反复栽的那个坑**（ADR-027）。

| 语域 | 读者 | 文体 |
|---|---|---|
| **运行时输出**（控制台 / CLI / **日志**里给人看的那部分） | 使用者，**当场看** | **说明书体**（本文件） |
| **仓库文档 / README** | 读者，**会反复查** | 书面说明，可以有 markdown |
| **提示词**（`persona.py` / `roles.py` / 工具返回给模型的） | **模型** | 强调语法有用，不受本文件约束 |
| **开发注记**（代码注释 / ADR / commit message） | 维护者 | 随便写，**别混进上面那三种** |

> ⚠️ **日志也算"界面文本"。** 2026-10-16 漏过一回：那句
> `已开始盯着拉起我的进程（PID 18300）` —— 所有者就是**从屏幕上看见它**才提的。
> 日志不是"内部调试信息"，**它就打在用户眼前**。

> **判断方法**：问自己"**这句话是给谁看的**"。
> 答"给以后翻资料的自己" → 那是注记，别往屏幕上放。
> 答"给现在坐在这儿的人" → 说明书体。

## 2. 规则（每条都有出处，不是我的偏好）

### 2.1 口语 → 书面

| ❌ | ✅ |
|---|---|
| 敲 `help` | 输入 `help` |
| 看命令 | 查看命令 |
| 起它 | 启动 |
| 没在跑 | 未运行 |
| 会涨 | 将提高 |
| 已经在跑 | 运行中 |
| 试着占用端口 | 尝试占用端口 |
| 要打 y 确认 | （去掉，或写"需确认"） |

**判据**：这个词**在设备说明书里会出现吗**？
"敲"不会，"输入"会。"起它"不会，"启动"会。

### 2.2 不拟人

| ❌ | ✅ |
|---|---|
| 这个窗口**管着机器人的命** | bot 会在此终端退出时同时终止 |
| 可私聊**它的人** | 可私聊用户 |
| **模型回了**：'在的' | 输出测试：'在的' |
| 跟**模型说一句话** | 输入测试 |

⚠️ "管着机器人的命"这种**比喻**看着生动，但：
- 它是**我的表达欲**，不是使用者的信息
- 所有者原话：**"这个位置都不应该有东西"**

### 2.3 不用第二人称「你」

| ❌ | ✅ |
|---|---|
| **你的** `.env` 里没有这些键 | `.env` 内未赋值键 |
| **要改它们的话**，照 .env.example 补上 | 可依据 .env.example 更改 |

去掉"你"之后，句子从**对话**变成了**提示**。

### 2.4 不用方位指代

| ❌ | ✅ |
|---|---|
| 日志会出现在**下面** | 开始输出日志 |
| 把**上面这个**地址填进 NapCat | 可填入 NapCat「HTTP 上报」 |

"上面/下面"在**滚动**的终端里根本指不准 —— 而且它默认读者正在盯着屏幕。

### 2.5 能省就省

| ❌ | ✅ |
|---|---|
| `1 个` / `5 个` | `1` / `5`（**去掉量词**） |
| `（可选：direct / delegated / hybrid）` | `（direct / delegated / hybrid）` |
| `（下次启动还是它）` | `（写入 .env）` |
| `它的长度是 35` | （去掉 —— 密钥长度本身就是个指纹，不该往外报） |

**"可选："这种词不传递信息** —— 括号里并列几个值，本来就是可选的。

### 2.6 短句用 `--` 连，别用句号切碎

| ❌ | ✅ |
|---|---|
| 命令台就绪**。**敲 help 看有哪些命令。 | 命令台就绪**--**输入 help 查看命令。 |
| 启动中（PID 17578）**。**日志会出现在下面。 | 启动中（PID 17578）**--**开始输出日志。 |

`--` 表示"**同一条提示的前后两半**"，句号表示"两件事"。
控制台里前者更常见。

### 2.7 术语统一，且用标准词

| ❌ | ✅ |
|---|---|
| 看图路线 | 视图模式 |
| 看图（与"识图"混用） | 统一一个 |

同一个东西在同一个界面里**只能有一种叫法**。
选词优先用**行业里的标准词**（"视图模式"是通行的），不用自造的口语（"看图路线"）。

**⚠️ 而且要和代码里的英文标识对齐。** 例子（所有者 2026-10-16 追问的）：

| ❌ | ✅ | 为什么 |
|---|---|---|
| 让它**闭嘴** | 使该群**静默** | `闭嘴` 口语之外**还带情绪**（像在训人） |
| 这个群**永远不开口** | 该群**静默** | `不开口` 是描述"嘴"的动作，**拟人** |
| （`沉默`） | **`静默`** | `沉默` 更文学、偏形容人；`静默` 是操作性术语，**且对得上代码里的 `silent`** |

**一条好用的判据**：**这个词在代码/配置里有没有对应的标识符？**
有（`silent`），中文就照着它选 —— 使用者在配置里看到的和界面上读到的**是同一个词**。

### 2.8 不用带情绪的词

界面是**中性的**。同一个意思，选那个**不带褒贬**的说法：

| ❌ | 读起来像 | ✅ |
|---|---|---|
| 让它闭嘴 | 训人 | 使该群静默 |
| 它会暂时不理人 | 抱怨 | 停止期间不响应消息 |
| 会很吵 | 评价 | 仅适用于调试 |

⚠️ 这条**比"书面 vs 口语"更隐蔽** —— 上面几个词都挺书面，
但它们**夹带了态度**，而界面不该有态度。

### 2.9 不在界面里推销、不打气、不解释动机

这些都不要出现在屏幕上：

- "一切正常"（说**通过**即可）
- "别担心 / 注意哦"
- "这是为了……"（**动机写在注释和 ADR 里**，不写在界面上）

## 3. 完整案例

`docs/contract.md` 是原始对照，**改动前先读那一份**。
下面只摘最能说明问题的两段：

**控制台横幅**

```
❌  saya 控制台。敲 help 看命令。
    start / end / restart / status + 全部设置命令
    end / restart / quit 要打 y 确认
    [!] 这个窗口管着机器人的命：它一关，机器人就停。

✅  saya 控制台--输入 help 查看命令。
    start / end / restart / quit / status
    [!] bot会在此终端退出时同时终止
```

三处改动：口语→书面、**删掉冗余**（"全部设置命令"help 里会说）、
**删掉比喻**。

**自检**

```
❌  可私聊它的人: 1 个（主人/管理/白名单），其余私聊一律不理
✅  可私聊用户: 1 （主人/管理/白名单），其余私聊无效

❌  你的 .env 里没有这些键（会走默认值）：SAYA_CV_MODEL_DIR
    要改它们的话，照 .env.example 补上。
✅   .env 内未赋值键（默认值）：SAYA_CV_MODEL_DIR
    可依据 .env.example 更改。
```

## 4. 怎么守住

- `tests/test_output_style.py` 扫**会出现在屏幕上的那些字符串**：
  `print(...)`、**`logger.*`**、`Outcome` / `Result` / `_say`、`BANNER` / `USAGE`。
  拦三类：**markdown**、**内部文档索引**、**已经改掉的口语词**（一份小名单）。
- ⚠️ **它拦不住"新的口语"** —— 机器判不了。
  名单里只有**我们逐个改过的**那几个词（`盯着` `崩了` `摘掉` `闭嘴`…），
  防的是回潮，不是全部。加新的界面文本时，**照着第 2 节人过一遍**。
- ⚠️ **文件范围是"全部"**，不是一份手写名单。
  这条也栽过：原来的名单是 7 个文件，而要改的日志在
  `watchdog.py` / `pipeline.py` / `core/tools.py` —— **一个都不在里面**，
  于是"加了防护"那一轮**什么都没扫到**。
- 拿不准就查 `docs/contract.md`：**他改过的地方就是答案**。
