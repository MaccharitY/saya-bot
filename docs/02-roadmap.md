### 0.2.0 的方向：**从聊天机器人到智能体**（所有者 2026-10-17 定调）

> 不是加新功能、修 bug，而是**从 bot 聊天到可基于 QQ 交互的智能体**：
> 自我决策、自主调工具、**对自己的实现方式有认知**。权限越大，安全问题越复杂。

**已经定了的**（见 ADR-038 / 039 / 040 / 049）：

- **运行时分三层**：接入 / 编排 / 智能体。判据：**不可逆或对外可见的一律在编排层**
- **智能体层用 dsh**（DeepSeek 官方 harness），**只做工具容器** ——
  ✅ 已实测可行（热启动 2.5–2.8 s、Linux 沙箱真的拦截、不用登录）
- **智能体的工具面：最多一个 OCR MCP，不接 CV / 检测**（ADR-049）。
  依据是 0.1 的实验：检测委派在计数与细粒度上显著更差，换强模型与开放词表都救不回来
- **每条消息都过智能体层**，多轮工具只在"她要工具"时发生（= 现有 `run_with_tools`）
- **视图模式改为按会话配置**，新增 `auto`

**范围和顺序（所有者 2026-10-17 定）**：

- **实验用 0.1 跑完**，代码冻结在 `v0.1.1`。它是**0.1 的交付物**。
- **0.2 不背实验**：测试集、对照组、分析脚本**留在 `pre/` 与 `experiment/`，
  不进 0.2 的范围**。0.2 只从实验里带走**一个能力**：按会话切换视图模式（ADR-040）。
- **`auto` 和智能体层是一起的，不能拆** —— 要选路线，她得先明白"这题要数数"，
  而"明白题目"和"决定调不调工具"是同一步。**所以 0.2 = 视图模式切换 + 智能体层。**
- **0.2 就在 `saya_bot` 这一个仓库里做**，不另起项目。建议用 worktree 隔离，
  `main` 继续跑现网。
