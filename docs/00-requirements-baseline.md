## 1. 背景与动机

项目所有者想做一个 QQ 群聊机器人：以**个人账号**身份（而非 QQ 官方机器人开放平台）在群里说话，核心模型用 DeepSeek，具备看图、接梗、记住人和事的能力。

同时，这门 AI/计算机视觉课程要求交一份 ~1000 词报告 + 小组 talk（见 [../pre/00-course-requirements.md](../pre/00-course-requirements.md)），选题是：**在模型应用里做图像识别时，"多模态大模型直接看图" 与 "MCP / 工具调用专用 CV 模型" 两条路线的优劣取舍**。

**两者是绑定的**：机器人就是实验平台，报告里的 results 用它的实测数据。这不是巧合，是本项目的核心设计约束——**工程侧必须预埋埋点与对照开关**，否则报告写不出来。

## 2. 目标 / 非目标

### 目标
- G1：一个能在真实 QQ 群里稳定收发消息、人格化说话的机器人。
- G2：能看懂群友发的图片并参与对话。
- G3：把群友消息当**不可信输入**处理，抗提示注入。
- G4：能接 ACG 梗（接入萌娘百科一类百科做检索增强）。
- G5：对**人**（群成员）和**事**（话题、约定）有可检索、可纠正、可遗忘的记忆。
- G6：能产出**可信的对照实验数据**，支撑课程报告。
- G7：任何时刻，一个新会话 clone 仓库 + 读文档就能接手。

### 非目标（明确不做，防止范围蔓延）
- N1：不做通用 QQ 机器人框架，不追求覆盖多平台（先服务单个账号、少量群）。
- N2：不做多实例/大规模并发的分布式部署。
- N3：不做模型训练或微调，只用现成 API。
- N4：**不做任何绕过 QQ 风控、规避封号、批量养号的对抗性手段**（伦理红线，见 CLAUDE.md）。
- N5：不做 Web 管理面板（除非后续明确要求）。

## 3. 功能需求

优先级含义：**P0 = 课程截止（2026-10-29）前必须有**；P1 = 核心体验，截止后补；P2 = 以后。

| ID | 需求 | 验收要点 | 优先级 |
|---|---|---|---|
| **FR-1** | **接入层收发消息**：以个人账号身份接入 QQ 群聊（非官方机器人） | 能收到群消息与私聊、能发文本与图片；**内核不依赖具体后端**，换后端只改一个 adapter | P0 |
| **FR-2** | **触发判定（"自动识别"）**：判断哪些消息该回、哪些该忽略 | 支持 @提及 / 关键词 / 概率 / 全回 四种模式，可配置；有群黑白名单、每群每分钟限流、不重复回复 | P0 |
| **FR-3** | **回复生成**：以 DeepSeek 为核心生成回复 | 有人格设定（可配置）；保持群聊语气而非客服腔；单条失败不影响整体 | P0 |
| **FR-4** | **防注入** | 群友内容一律视为不可信数据，与系统提示严格隔离；越狱/越权请求被拒；**不泄露系统提示、不泄露密钥**；工具调用走白名单 | P0 |
| **FR-5** | **多模态看图** | 能接收群友图片、识别内容并自然参与对话；能理解表情包/梗图 | P0 |
| **FR-6** | **接梗 / 知识增强** | 接入萌娘百科一类百科，回答角色/作品/梗相关问题；回答要标注来源；检索失败要优雅降级 | P1 |
| **FR-7** | **记忆（对人对事）** | 记住群成员画像与偏好、记住话题与约定；可检索、**可纠正**、**可遗忘**（要有删除入口）；记忆不串群 | P1 |
| **FR-8** | **可观测 / 埋点** | 每次模型调用记录：输入摘要、输出、token 数、耗时、成本、命中路线。**这是 pre 数据的唯一来源** | P0 |
| **FR-9** | **双路线实验开关** | 同一看图任务可切换「MLLM 直接识别」/「MCP·工具调专用 CV 模型」两条路线，并打上实验标签，便于对照统计 | P0 |
| **FR-10** | **适配层可扩展** | 后续能加官方 QQ 开放平台机器人 / 其他 IM 后端，且不改内核 | P1 |

## 4. 非功能需求

| ID | 需求 | 说明 |
|---|---|---|
| NFR-1 | **可继承性** | 全部决策、进度、需求落盘；新会话无需历史对话即可接手 |
| NFR-2 | **密钥零落盘** | 只用环境变量 / 本地 `.env`（已 gitignore）。代码、文档、提交历史、issue 里都不出现 |
| NFR-3 | **可测试** | 内核逻辑不依赖真 QQ，能用 Mock 事件做自动化测试（见 ADR-003） |
| NFR-4 | **成本可控** | 有每次调用与每群的预算上限；限流；避免无意义调用 |
| NFR-5 | **可配置** | 人格、触发策略、模型、实验开关全部走配置，不写死在代码里 |
| NFR-6 | **健壮性** | 单条消息处理失败不崩；异常有日志；重启后状态可恢复 |

## 5. 约束

- **时间**：报告 + slides 截止 **2026-10-29**（Week 9 周四）。talk 在 Weeks 7-9，**具体日期待确认**（今天 2026-10-15 已是 Week 7，可能很近）。
- **环境**：单机 Windows 11；Python 3.11.9；Node 24.21；git 2.55；**无 docker**、**无 gh CLI**。
- **硬件**：**RTX 5070 Ti Laptop GPU，12GB 显存** → 本地跑专用 CV 模型（YOLO / GroundingDINO / PaddleOCR 等）可行，路线 B/C 不必依赖云端 CV API。
- **QQ 客户端**：已装（`D:\Program Files\Tencent\QQ\QQ.exe`），满足接入 NapCat 的前提。
- **报告语言**：**中文**（课程要求的 background / methodology / results / conclusion 四节标题保留英文原样）。
- **选题口径**：**三条路线**（A 纯多模态模型 / B 外包专用 CV + 编排 / C 混合），不是简单比"谁更好"（ADR-007）。
- **模型**：DeepSeek（经 CC Switch 代理，也可直连官方）。**注意**：`deepseek-v4.1-flash` 多模态可看图；纯文本模型不能看图，选型时别切错。
- **风险**：个人账号接非官方协议有封号风险，知情接受。
