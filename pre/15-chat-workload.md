## 1. 要回答什么

前四轮用的是 PerceptionBench 的标准题。它回答"三条路线在受控任务上谁更强"，
但不回答"群聊里的图到底长什么样、这三条路线在真实图上表现如何"。

两个问题：

1. **真实工况的分布**：类型、尺寸、动图比例、文字密度。
2. **三条路线在真实图上的表现**：准确率、延迟、成本、失败率、空证据率。

## 3. 标注体系

每张图一行：

| 字段 | 取值 |
|---|---|
| `type` | `text_screenshot`（界面/聊天/游戏结算）、`photo`、`meme`（表情包）、`chart_doc`（图表/文档）、`other` |
| `animated` | 0 / 1 |
| `text_density` | `none` / `low` / `high` |
| `has_people` | 0 / 1 |
| `notes` | 一句话 |

**抽样**：按 `type` 分层，目标 **60 张**（每类至少 10；某类不足则全取）。
单标注者；另抽 10 张做第二人复核，报告一致率。

## 4. 问题与答案怎么来

真实群聊没有标准问题。为让三条路线可比，需要为抽样图**构造**问题：

- 只问图上能回答、答案唯一且短的问题；
- 每题给 `gold` 与可接受同义词；
- **由所有者确认**（避免把"我以为群友会问"当成事实）；
- 每图 1 题，共 60 题；题型尽量覆盖读字、识别、计数、定位。

> ⚠️ 这是**受控问题 + 真实图片**的混合设计：图片分布是真的，问题是我们拟的。
> 报告里必须写明这一点，不能宣称"复现了群聊问答分布"。

## 5. 跑什么

- 三条路线：`direct` / `delegated` / `hybrid`，配对设计；
- 思考预算：`none`（部署设置）；若时间允许，`direct` 补一组 `max`；
- 工具：与主实验一致（YOLO11x + 云端 OCR，按 v0.1.3 配置）；
- 每图每题每条路线各一次。

## 6. 指标

| 指标 | 说明 |
|---|---|
| 准确率 | 判官；另做人工抽检（≥20%） |
| 分层准确率 | 按 `type`、`text_density` 拆 |
| 端到端延迟 | P50 / P95 |
| 成本 | 按三档计价（缓存命中 / 未命中 / 输出） |
| 失败率 | 调用失败、超时 |
| **空证据率** | 工具在真实图上什么也没检出/读出的比例 —— 群聊工况的关键指标 |
| 证据量 | OCR 字符数、检测框数 |

## 7. 分析口径

- **不与 PerceptionBench 的总分直接比**：两边的任务分布不同。
  只在**同类型内部**比较（例如真实文字截图 vs 基准的 OCR 层）。
- 主分析仍用配对风险差 + 按图重抽样的区间；
  样本只有 60，**只报效应量与区间，不宣称显著性**（除非效应很大）。
- 负结果照常报：空证据率、失败案例、判官与人工不一致的题。
