# 16 · 机制与价值：为什么 VLM 更准，以及群聊机器人该怎么做

> 2026-10-18。这份文档回答两个问题：
> **深度** —— VLM 的注意力机制为什么能带来更好的识图准确度，为什么会在一些任务上
> 反过来压过专用 CV / 委派路线；
> **价值** —— 落到群聊工况，具体该怎么改机器人。
>
> ⚠️ 引用纪律：本文件的论文均已打开 arXiv 摘要页核对（2026-10-18），
> 具体实验数字以原文为准；我们的数据来自 `pre/experiments/`。

## 1. 机制：VLM 到底在"看"什么

### 1.1 一条图像 → patch → token 的链路

VLM 的视觉侧通常不是"图片整体过一遍 CNN"，而是：

```
图片 → 切成 14/16 px 的 patch → ViT 编码 → 投影到词向量空间
     → 和文字 token 拼在一起 → LLM 自注意力 → 生成
```

ViT 的原论文（Dosovitskiy 等，2020）证明：**不需要卷积**，纯 Transformer
直接作用在 patch 序列上，只要预训练数据够大，分类精度就能超过当时的 CNN。
关键在于它没有把"局部性"写死进结构，而是让模型自己学。

### 1.2 为什么这带来"反复看"的能力

自注意力的性质是：**输出端的任意 token，可以在每一层 attend 到任意一个 patch**。
这带来两个直接后果：

1. **全局感受野从第一层就有**。CNN 要靠堆层数扩大感受野；ViT 一步到位。
   计数、空间关系这类需要"看全图"的任务，天然占优。
2. **推理过程可以重新分配注意力**。模型生成中间推理 token 时，这些 token
   又成为新的查询，继续回看图像的不同区域。开思考预算后，这条回路被拉长。

2025–2026 的两篇工作把这件事做得更显式：

- **VLM-R³**（arXiv 2505.16192）：让模型自己决定"什么时候需要更多视觉证据、
  该看哪里"，把子图裁剪/放大后**织回思维链**。作者明确指出，复杂任务需要
  "dynamic and iterative focusing on and revisiting of visual regions"。
- **SIEVE**（arXiv 2603.14117）：更进一步，认为 VLM **内部已经有**重新取用
  视觉证据的信号，不需要外部裁剪/重编码；在推理链里注入显著区域的嵌入，
  多个基准平均 **+8%**。

这正好解释了我们的第四轮：同一张图、同一个模型，开满思考后 counting 从
**33% → 60%**；而只拿到工具文本的委派路线 **3% → 3%**。
**能重新看图的路线才吃得到推理红利。**

### 1.3 但注意力不是万能的：编码器仍是天花板

MMVP（Tong 等，2024）构造了"CLIP-blind pairs"——人类看来明显不同、
CLIP 却认为相似的成对图像。前沿多模态模型在九类基本视觉模式上系统性出错，
且错误与 CLIP 的失败高度相关。

我们的数据同向：direct 开满思考也只有 **53%**（counting 60%），
没有到"看着就能数对"。**注意力能重新分配已有的视觉证据，但补不回编码阶段
丢掉的信息。**

### 1.4 那为什么专用检测器反而更差？

三条证据：

1. **接口不同，不是架构不同**。CNN 检测器的输出是"固定类别 + 框 + NMS"。
   NMS 的设计目标就是压掉重叠框，而计数要的恰恰是"别压"。
   它不为枚举优化，只为定位/分类优化。
2. **词表是硬门**。COCO 80 类覆盖不了"兔子/棋子/数字标签"。
   换 YOLO11x 精度更高，但词表没变，所以第三轮 12% → 11%。
3. **开放词表只带来小幅提升**。把正确名词直接交给 YOLOE-26x（oracle 词表），
   全量 120 题上 delegated 从 10.8% 到 15.0%（+4.2pp），去 OCR 从 5.6% 到 10.0%；
   排序不变，B 仍远低于 D。瓶颈从"认不认识"变成了"能不能数全"——
   **实例枚举**本身超出了检测器的设计目标。

注意边界：这不是"Transformer 全面碾压 CNN"。ConvNeXt（Liu 等，2022）
用现代训练配方把纯 CNN 做到 87.8% ImageNet top-1，追平 Swin；
COCO 检测上 YOLO26x 仍有 57.5 mAP。**被碾压的是"固定词表 + 一次性框输出"
这套接口**，不是卷积算子本身。

### 1.5 注意力还会"看错地方"

ViT 的注意力并不总是干净的：Registers 那篇（Darcet 等，2023）发现，
ViT 特征图里会出现**高范数的背景 token**，被模型挪去做内部计算，
导致注意力图出现伪影。加一组额外的 register token 就能修好，并让
稠密预测和注意力图都更平滑。这说明：**注意力是可解释的，但不是自动正确的**；
分辨率、token 预算、背景占比都会影响它看哪里。

对我们的直接含义：**给模型更高分辨率、更聚焦的图，比让它硬看一张缩略图更有效**。
Qwen2-VL（Wang 等，2024）的 dynamic resolution 就是这个思路：
按原图分辨率生成不同数量的视觉 token，而不是统一缩放到固定尺寸。

## 2. 价值：群聊机器人具体怎么改

以下按"预期收益 / 改动成本"排序。前三条不需要换模型。

### P0 · 按图片类型分流（最大收益，零模型改动）

真实工况数据（60 张）：

| 类型 | direct | delegated | hybrid |
|---|---:|---:|---:|
| 文字截图 25 | 0.92 | 0.80 | 0.92 |
| 表情包 18 | 0.83 | **0.11** | 0.72 |
| 照片 11 | 0.64 | 0.27 | **0.82** |

做法：

- **文字截图 / 表情包 → 直连**（默认 `none`）；
- **照片 → 混合**（SoM 标注 + 原图）；
- **委派只在"工具有证据"时用**：截图上的 OCR 通常有产出，表情包上 61% 本来没字。

分类器不需要模型：OCR 字符数 + 宽高比 + 颜色方差就能分开。
我们的数据里，文字截图的 OCR 中位 274 字符，照片/表情包 27–32 字符。

### P0 · 空证据兜底（避免"工具什么都没说还在硬答"）

委派/混合在调用工具后，如果检测和 OCR **都为空**，直接退回直连，
而不是让主模型对着一句"没有检测到任何目标"猜。
真实工况里：截图检测 52% 为空、表情包 OCR 56% 为空。
这个兜底可以把"工具没证据"的题从 11–27% 拉回直连水位。

### P1 · 难点才开思考（延迟/成本可控）

`max` 把 direct 从 53% 拉到 60%（counting），代价是端到端 1.06 s → 33.9 s、
成本 ¥0.07 → ¥9.97 / 120 题。**逐条都开不可行**。

建议触发条件（任一）：

- 题目里有计数/比较/定位意图（"几个""哪个""在哪"）；
- 图片分辨率高、文字密（OCR 字符数 > 150）；
- 用户显式要求"仔细看"；
- 同一张图上一轮回答被用户纠正。

其余情况保持 `none`。

### P1 · 文字截图走高分辨率，而不是缩略图

真实截图多是 1080×2400，字很小。Qwen2-VL 的 dynamic resolution 和
我们的 OCR 数据都指向同一件事：**分辨率决定能不能读清**。
工程上最简单的做法：按最长边分块（tiling）或对目标区域裁剪放大后再送模型；
这比换更大的模型便宜得多。

### P2 · "再看一眼"：外部裁剪 + 二次提问

VLM-R³ / SIEVE 说明模型内部有重访能力；我们的模型没有开放区域接口，
但可以用**外部裁剪**模拟：

1. 第一轮回答后，如果题目是计数/定位且答案置信度低；
2. 让模型给出大致区域（或直接用检测框）；
3. 裁剪/放大该区域，再问一次"这里数一遍"。

成本是多一次调用，但只对少数题触发。这是 0.2 智能体层最值得做的能力之一。

### P2 · 缓存友好的提示词结构

`none` 下 direct/hybrid 的输入缓存命中 60%+，delegated 为 0%。
⚠️ **但这不完全是架构优势**：实验是逐条轮转，混合紧跟在同题的直连之后，
前缀（问题+图片）完全相同；直连第三轮的命中还包含同题重跑。
工程上能带走的结论只有一条：**稳定的前缀放前面**，每图变化的证据放最后。

### P3 · 群聊行为本身

- **每条消息最多回一条**（现有约束，保持）；
- 引用触发消息，避免"答非所问"；
- 连续多图消息按图分别处理，不要把多张图混成一个问题；
- 对表情包不做 OCR 方向的解释，直接按图回答。

## 3. 怎么验证这些改动

现有的 60 张真实工况图就是回归集（`pre/experiments/chat-real/`）：

| 指标 | 基线 | 目标 |
|---|---:|---:|
| 总体准确率 | direct 83% / delegated 48% | 分流后 ≥ 88% |
| 表情包委派事故 | 11% | 0（不再走 B） |
| 空证据兜底触发率 | — | 记录并报告 |
| 端到端 P50 | 1.14 s | ≤ 1.5 s（`none` 为主） |
| 成本 / 60 题 | ¥0.09 | ≤ ¥0.12（含少量 max） |

每次改动后在同一批图上重跑，**先看分流是否正确，再看准确率**。

---

## 4. 局限

- 机制部分是文献 + 我们的间接证据，没有做注意力可视化；
- 真实工况只有 60 张、单群、问题是我们拟的；
- "再看一眼"的外部裁剪尚未实现，只是设计。
