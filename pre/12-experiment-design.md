# 12 · 实验设计（三条路线的操作定义）

> 状态：**v1（2026-10-15，经项目所有者确认路线划分）**
> 🎯 这是**实验自变量的定义** —— 报告的每一条结论都建立在这份定义上。**改这里之前先想清楚。**
> 代码实现：`services/vision.py`；架构决策：`../docs/01-architecture.md` ADR-005；文献依据：`11-literature.md`。

---

## 1. 共同前提：同一个大脑

**三条路线共用同一个大脑：`deepseek-v4.1-flash`（v41f）**，它负责大部分事（对话、编排、推理）。

**唯一变化的东西：视觉任务由谁做。**

这个约束是硬性的。如果三条路线用了不同模型，测出来的就是"模型差异 + 架构差异"的混合物，**老师/TA 一句"会不会只是模型本来就强"就能问倒**。

## 2. 三条路线

### 路线 A · 纯自看（`direct`）

```
图片 → v41f（多模态）→ 答案
```
图片**直接进主模型 prompt**，视觉任务全部由 v41f 本体承担。

### 路线 B · 纯外包（`delegated`）

```
图片 → 附属（经 MCP）→ 文本结果 → v41f → 答案
```
图片**完全不进主模型**。附属处理图片，只把**文本**交给 v41f。
→ 注意这个干净的可测性质：**路线 B 里主模型根本不需要视觉能力**。

### 路线 C · 协同（`hybrid`）

```
图片 → 附属 → 结构化产物（检测框 / 掩码 / 编号标注）
                    ↓
        [原图 + 产物] → v41f（多模态）→ 答案
```
附属做**可量化的部分产物**（定位、分割、计数、编号），v41f 基于"图 + 结构化产物"做**语义推理**。这正是 Set-of-Mark 的做法。

## 3. ⚠️ 唯一没定、但必须先定的东西：**"附属"是什么**

这一项**尚未确认**，它决定了 B / C 两条路线**到底证明了什么**：

| 选法 | 附属 = | 路线 B 实际是 | 证明的是 |
|---|---|---|---|
| **B1** | **通用视觉大模型**（GLM-4.6V / Qwen3-VL 之类） | **模型级联**：模型甲看 → 文本 → 模型乙答 | "**换一只眼睛**有没有用" |
| **B2** | **专用 CV 模型**（YOLO / GroundingDINO / PaddleOCR / SAM） | **工具化**：把可量化子任务交给确定性模型 | "**把精确任务工具化**有没有用" |

### 文献怎么预测（见 `11-literature.md`）

- **B2 有强证据支持**：MLLM 在计数、小目标、OCR、细粒度、空间关系六类任务上有系统性短板（CountQA、MMVP、CC-OCR、POPE、COUNTS、LMM-Det 等）。
- **B1 的收益存疑**：它主要价值是"**主模型没有视觉能力时补一只眼睛**"。而 v41f **本来就能看图**，所以"再套一个视觉模型"可能只是白交一层开销——**这本身就是一个值得测的结论**。
- **路线 C 的代表作 SoM 用的是分割模型出候选** → 属于 B2 思路。

### 建议：**两种都做**

- 工作量增加有限（换一个附属实现而已）
- 能回答一个更有价值的问题：**到底是"换眼睛"有用，还是"上工具"有用？**
- 时间不够时**优先 B2**——文献支持最强，且 B2 的附属和路线 C 可以复用同一套

## 4. 实验组矩阵

| 路线 | 附属 = 通用 VLM | 附属 = 专用 CV |
|---|---|---|
| **A** 纯自看 | —（不需要附属） | — |
| **B** 纯外包 | **B1** | **B2** |
| **C** 协同 | —（无意义：通用 VLM 出不了候选框） | **C** |

**共 4 个实验组：A / B1 / B2 / C。**
**最小集合：A / B2 / C**（覆盖三种架构思路，且是文献预测差异最大的组合）。

每条 trace 事件必须打 `route` 与 `experiment_tag` 标签，否则事后对不上账。

## 5. 测试集

沿用 [`10-research-notes.md`](10-research-notes.md) 第 5 节：

- **规模**：同批 **≥100 张图**
- **五个难度层**（每层约 20 张，**与文献的六类短板一一对应**）：
  1. 常见类（猫、车、食物）—— 预期三路线接近
  2. 长尾 / 细粒度（具体角色、特定型号）—— 预期 A 略优（语义知识）
  3. 小目标 —— 预期 B2/C 明显优
  4. **多目标计数** —— 预期差异最大（文献反复证伪 MLLM 计数）
  5. 含文字（OCR）—— 预期 B2/C 明显优
- **控制**：固定 prompt 与温度；**配对设计**（同图同问）；报 mean ± std，做配对显著性检验

## 6. 指标

| 指标 | 怎么量 |
|---|---|
| 准确率 | 分类 top-1 ／ 检测 mAP@0.5 ／ 计数 MAE（按测试集层次分别报） |
| 延迟 | 端到端 **P50 与 P95**（不是只有平均值） |
| 成本 | 见下 |
| 失败率 | 超时 / 报错 / 拒答 |
| 幻觉率 | 在图中不存在的东西上编造（POPE 式探测） |
| 可解释性 | 能否给出 bbox / 置信度 / 依据 |

## 7. ⚠️ 成本口径（答辩最容易被问的点）

- 路线 **A / B1 / C 的模型部分**：按 API token 计费 → 有明确账单
- 路线 **B2 / C 的 CV 部分**：本地算力 → **没有 API 账单**，只有硬件折旧 + 电费

**两者不能直接相加。** 报告里必须分列两种口径：

- **边际 API 成本**（每千次调用多少钱）
- **本地算力摊销**（按 GPU 时价折算）

并说明：本地模型是**前期投入换长期低边际成本**，图片量大时优势才显现。**忽略这一点的对比是无效的。**
