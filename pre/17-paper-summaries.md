## 1. ViT：An Image is Worth 16x16 Words

**出处**：Dosovitskiy 等，2020，arXiv:2010.11929；ICLR 2021。【摘要】

### 一句话

把图片切成 patch，当成"词"送进标准 Transformer；只要预训练数据够大，不用卷积也能超过当时的 CNN。

### 问题：卷积是不是必要的

在 ViT 之前，计算机视觉的主干几乎被 CNN 统治：AlexNet、VGG、ResNet 一路下来，卷积的局部连接、权重共享、平移等变性被当成视觉任务的"正确先验"。Transformer 进视觉的尝试主要有两种：与 CNN 混用（CNN 提特征、Transformer 做关系建模），或者只替换 CNN 的某个部件、整体仍保留卷积结构。作者问的是一个更彻底的问题：**如果把图像也当成序列，让自注意力自己学空间关系，行不行？** 卷积的先验在小数据时是优势，但可能限制大模型的上限；而 NLP 的经验说明，数据足够大时，Transformer 的通用结构可以学得更好。

### 方法：把图变成 token 序列

1. 把一张 H×W 的图切成固定大小的 patch（论文主结果是 16×16；也试了 32×32）。每个 patch 拉平后做**线性投影**，得到一个 token。
2. 所有 patch token 加上**位置编码**，前面再拼一个可学习的 `[CLS]` token，组成序列。
3. 序列直接送进标准的 Transformer 编码器（多头自注意力 + MLP），**不做任何卷积**。
4. 预训练用大规模数据（论文用了 ImageNet-21k、JFT-300M 级别的数据），然后迁移到下游基准；微调时替换分类头。

关键设计是**没有把图像的特殊性写进结构**：patch 之间从第一层就可以互相注意，感受野是全局的；位置信息只靠位置编码提供。代价是注意力对 token 数是平方复杂度——一张高分辨率图会产生大量 patch，计算与显存都会吃紧。这一点后来直接影响了 VLM 的分辨率策略：切块、动态分辨率、只对感兴趣区域放大，都是在绕这个约束。

论文还讨论了"混合架构"：在 ViT 前面接一个 CNN 提特征，用小数据时效果更好。这说明作者并不认为卷积一无是处，而是认为**在足够大的数据下，纯注意力的上限更高**。

### 结果【摘要】

在 ImageNet、CIFAR-100、VTAB 等基准上，ViT 与当时最强的 CNN 相比达到同等或更好的结果，而且**训练所需算力显著更少**。摘要强调的前提是"在大规模数据上预训练"；这也暗示了它的软肋：数据不够大时，卷积的归纳偏置仍然有用。

注意摘要说的是**分类**基准与**训练算力**，不是推理延迟、检测精度或开放词表能力。论文报告的具体精度（不同 ViT-B/L/H 变体）需要回原文核对，报告里不要凭印象写数字。

### 局限与注意

- **数据饥饿**【背景】：ViT 在中小数据上不如同规模 CNN；后续 DeiT 用蒸馏与强增广缓解了这一点。
- **分辨率固定**【背景】：位置编码与 patch 数绑定，换分辨率要插值。
- **它证明的是分类**，不是检测、计数或开放词表。把它写成"ViT 让模型会看图"是过度引申；它证明的是"视觉主干可以不用卷积"。
- 论文的比较是**同算力/同数据条件下的分类精度**，不是"Transformer 在所有视觉任务上全面优于 CNN"；ConvNeXt（2022）后来用现代 CNN 配方追平了 Swin，说明训练配方与数据规模同样关键。

### 与我们项目的关系

路线 A 的架构前提：图片可以进入和语言同一套注意力机制。我们的 direct 路线之所以能"反复看"，底层就是视觉 token 与文本 token 共享自注意力。但 ViT 只回答"能不能不用卷积"，**不回答"能不能数对"**——后者要看 MMVP 和 Counting to Four。

报告里可以这样用：Background 讲路线 A 时，用 ViT 说明"视觉主干不必是 CNN，VLM 可以让图像和文字共享注意力"；不要用它证明"VLM 的识图更强"。


### 进一步理解：全局注意力到底改变了什么

卷积的感受野是逐层扩大的：浅层只看邻域，深层才看全局。ViT 从第一层开始，任意两个 patch 就可以直接交互，注意力距离不是问题；代价是它必须从数据里学"邻近的 patch 更相关"这件事，而不是像卷积那样天生知道。这解释了为什么 ViT 需要大数据：**它把归纳偏置从结构里拿掉，换成了从数据里学**。

另一个常被忽略的点是 token 数决定计算量。16×16 patch 下，一张 224×224 的图是 196 个 token；分辨率翻倍，token 数变四倍，注意力计算变十六倍。后来的高分辨率 VLM 用切块/动态分辨率，本质上是在"看得清"和"算得起"之间做取舍。

### 在报告里怎么写

- Background 讲路线 A 时：一句话"视觉主干可以不用卷积，图像 patch 能与文字共享同一套注意力"。
- 不要写"ViT 让模型获得了视觉理解"；写"ViT 提供了把图像接入语言模型注意力机制的架构基础"。

### 读原文重点

patch embedding 的实现细节、预训练数据规模、以及"数据量 vs 归纳偏置"的消融；顺便看论文对"混合架构（CNN + Transformer）"的讨论，能帮助理解为什么后来的 VLM 仍常用 ViT 而不是纯 CNN 主干。

## 2. MMVP：Eyes Wide Shut?

**出处**：Tong 等，2024，arXiv:2401.06209（CVPR 2024，会议归属待核）。【摘要】

### 一句话

多模态模型的视觉能力没有想象中好：在人类看来明显不同、但 CLIP 也分不清的成对图像上，前沿模型会系统性出错。

### 问题：视觉编码器是不是瓶颈

当时的多模态模型，能力提升主要来自 LLM 的推理；视觉部分通常只是 CLIP 式的实例级对比预训练。CLIP 的训练目标是"图文对是否匹配"，学到的是一种**实例级**的语义相似度：同一张图的不同视角、不同细节，只要语义相近，就可能被压到相近的嵌入。作者问：**视觉本身够好吗？** 如果视觉编码器丢掉了信息，后面再强的语言推理也补不回来。这个问题对"路线 A"是致命的：如果瓶颈在编码器，那么"换更大的语言模型"不会解决问题。

### 方法：从 CLIP 的盲区构造基准

1. 比较 CLIP 的视觉嵌入空间与纯视觉自监督学习的嵌入空间，找出 **"CLIP-blind pairs"**：人类看来差异明显、CLIP 却认为相似的成对图像。
2. 用这些成对图像构造 **MMVP 基准**，覆盖九类基本视觉模式；题目都是人类觉得简单、答案唯一的问题。
3. 评测当时的前沿多模态模型（包括 GPT-4V），并检查模型出错的位置与 CLIP 编码器失败的位置是否相关。
4. 提出 **Mixture of Features（MoF）**：把 CLIP 特征与视觉自监督特征混合，作为初步补救。

这套设计的巧妙之处在于：它不是随机找难题，而是**从编码器的失败反推模型的失败**——如果模型在 CLIP 分不清的图上出错，说明错误确实来自视觉表示，而不是语言推理。九类模式的具体清单与构造细节需要回原文核对；报告里如果要列举，先查表。

### 结果【摘要】

- 前沿系统在 MMVP 上**系统性失败**，且经常给出编造的解释；
- 模型出错的位置与 CLIP 编码器失败的位置**高度相关**；
- MoF 能显著改善视觉 grounding。

摘要没有给出各模型的具体分数；报告里如果要写"某模型多少分"，必须回原文核对。

### 局限与注意

- 基准规模不大，题目集中在"CLIP 盲区"这一类，不代表所有视觉任务；
- 结论是"编码器是瓶颈之一"，不是"所有错误都来自编码器"；
- 它是诊断性工作，不是新模型；引用时不要说"MMVP 提出了解决方案"。
- 对中文群聊的图（UI 截图、表情包）是否同样适用，需要外部效度验证——我们的真实工况实验算是一次侧面检查。
- 论文的模型名单是 2024 年的，引用时不要把它当成"当前 SOTA"。

### 与我们项目的关系

这是"路线 A 的上限由视觉编码器决定"的核心证据。我们的 direct 开满思考也只有 53%（counting 60%），和这条结论一致：**推理能重新分配已有的视觉证据，但补不回编码阶段丢掉的细节**。报告里用来解释"为什么开思考也到不了 100%"。


### 进一步理解：CLIP 为什么会"盲"

CLIP 用图文对做对比学习：一张图与它配对的文本拉近，与同批其他文本推远。这个目标奖励的是"这张图整体在讲什么"，而不是"图里两个相似区域有什么细微差别"。当两张图语义相近、但局部细节不同（朝向、数量、小对象、结构关系），CLIP 可能把它们压到相近的嵌入——这就是 CLIP-blind pair 的来源。

MMVP 的价值不只是"模型分数低"，而是**把错误定位到编码阶段**：如果模型在 CLIP 分不清的图上出错、在 CLIP 分得清的图上不出错，那么"换更大的语言模型"不是解药。MoF 的思路也由此而来：既然 CLIP 特征丢了细节，就补一组纯视觉自监督特征。

### 在报告里怎么写

- 用来解释"为什么 direct 开满思考也只有 53%"：编码器是天花板，推理只能重分配已有证据。
- 不要写"MMVP 证明 VLM 不会看图"；写"MMVP 给出了视觉编码器是瓶颈之一的证据"。

### 读原文重点

九类视觉模式具体是什么、CLIP-blind pairs 怎么构造、MoF 的增益幅度、各模型的具体分数。

## 3. HuggingGPT：Solving AI Tasks with ChatGPT and its Friends

**出处**：Shen 等，2023，arXiv:2303.17580（NeurIPS 2023，会议归属待核）。【摘要】

### 一句话

让 LLM 当控制器：把用户请求拆成子任务，从 Hugging Face 里挑模型执行，再把结果汇总成回答。

### 问题：模型很多，但不会自己组合

不同领域、不同模态的 AI 模型很多，但它们不能自主组合起来解决复杂任务。2023 年前后，LLM 展现出语言理解、生成、交互和推理能力；一个自然的想法是：**能不能让 LLM 当调度器，把海量专用模型组合起来？** 这比"再训练一个全能模型"便宜，也比"人工写死流水线"灵活。Hugging Face 上有大量带功能描述的模型，正好提供了"可被选择的工具库"。

### 方法：四个阶段

1. **任务规划（Task Planning）**：把用户请求拆成可执行的子任务；
2. **模型选择（Model Selection）**：根据 Hugging Face 上每个模型的功能描述，为子任务挑模型；
3. **任务执行（Task Execution）**：调用选定模型，拿到结果；
4. **响应汇总（Response Generation）**：把各子任务的结果组织成最终回答。

语言在这里是**通用接口**：模型描述、任务描述、中间结果都用自然语言表达。论文的定位不是"某个视觉任务的 SOTA"，而是"LLM 作为编排器"的可行性。它把"模型能力"和"模型调度"分开了：LLM 不需要自己会检测、分割、语音识别，只需要会**选**和**编排**。这套思想后来以 function calling、agent、MCP 等形式延续下来；但 HuggingGPT 是**范式**，MCP 是**协议**，两者不能混为一谈。

### 结果【摘要】

在语言、视觉、语音等多类任务上展示了可行性，说明这条路径可以跨模态、跨领域扩展。摘要没有给出具体基准分数。

### 局限与注意

- **依赖模型描述的质量**：模型选择靠 Hugging Face 的功能描述，描述不准就选错【背景】；
- **错误会沿流水线传播**：规划错、选错、执行错，任何一步都会污染最终回答；
- **成本与延迟**：多次模型调用 + LLM 推理，端到端开销大；
- 它不是受控实验，不能拿来直接比较"委派 vs 直连"的准确率；
- 工具库的覆盖决定了能力上限——这也是我们实验里最关键的变量。

### 与我们项目的关系

路线 B 的范式原型：主模型不直接看图，而是调用专用模型。它隐含一个前提——**工具能覆盖任务所需的类别与能力**。我们的实验正是在这个前提不成立时（COCO 80 类覆盖不了测试题）看到委派崩掉。报告里用它说明"B 不是新想法，而是有明确前提的工程范式"。


### 进一步理解：编排器的三个失效点

把 LLM 当控制器，看起来只是"多调几次模型"，实际上有三个独立的失效点：

1. **规划**：请求拆错，后面全错；
2. **选择**：模型描述不准或工具库没有合适模型，选错；
3. **执行**：工具本身失败、超时、输出格式不对。

HuggingGPT 的价值在于把这三个阶段显式分开，让每一段都可以被检查；它的风险也在这里——**误差会沿流水线累积**。这解释了为什么"委派路线"在真实系统里往往不是败在模型不够聪明，而是败在工具覆盖与错误传播。

### 在报告里怎么写

- 用一句话定义路线 B："LLM 做控制器，专用模型做执行"。
- 紧接着写它的前提："工具库必须覆盖任务所需的类别与能力"——这是我们实验的切入点。


### 答辩时可能被问

- **"这和 function calling / MCP 有什么区别？"** HuggingGPT 是**范式**（LLM 做编排），function calling 是模型能力，MCP 是**协议**；三者层级不同。
- **"为什么不直接用一个全能模型？"** 成本、工具覆盖、可替换性；HuggingGPT 的答案是"用现成专家模型组合"，代价是流水线复杂。

### 读原文重点

任务规划与模型选择的具体实现、失败案例分析、以及多模型调用的开销。

## 4. VipAct：Visual-Perception Enhancement via Specialized VLM Agent Collaboration

**出处**：Zhang 等，AAAI 2026，arXiv:2410.16400（Comments 明确 AAAI 2026）。【摘要】

### 一句话

用 orchestrator + 多专家 agent + 视觉专家模型，补 VLM 在细粒度、像素级感知上的短板。

### 问题：细粒度感知是 VLM 的软肋

VLM 在需要像素级细节的细粒度视觉感知任务上仍然吃力；如何让它们在这些任务上获得更完整的推理？这和 MMVP 的结论呼应：不是"模型不会推理"，而是"输入到推理之间的视觉证据不够细"。作者的选择不是训练一个更大的 VLM，而是**把专用视觉专家接进来**，让它们提供高精度感知信息，再由多个 agent 分工处理。

### 方法：三层协作

- **Orchestrator agent**：负责任务需求分析、规划与协调；
- **专用 agent**：分别处理具体任务（如图像描述）；
- **视觉专家模型**：提供高精度的感知信息；
- 整体是多 agent 协作 + 工具调用，把"规划、推理、工具使用"串起来。

和 HuggingGPT 相比，它更强调**专家模型**与**多 agent 分工**：不是让一个 LLM 从头到尾调工具，而是让不同的 agent 各管一段，orchestrator 负责协调。消融里还检查了"多 agent 协作"和"图像输入对任务规划"的作用，说明作者关心的是**系统设计**而不是单点模型能力。

### 结果【摘要】

- 在多种视觉感知任务上超过当时的基线；
- 消融显示：多 agent 协作对激发更细致的 System-2 推理有作用；**图像输入对任务规划也重要**；
- 错误分析总结了 VLM 在视觉感知上的固有局限。

摘要没有给出具体分数与数据集清单；引用具体数字前必须开原文。

### 局限与注意

- 多 agent 流水线复杂，成本与延迟高于单次调用；
- 效果依赖专家模型的质量与覆盖；
- 它说明"委派在工具有效时成立"，不说明"委派总是优于直连"。
- 与 HuggingGPT 一样，它不是受控的三路线对比；不要把它当成"B 优于 A"的证据。
- 论文的模型与基准是 2024–2026 年的，引用时要标明时间。

### 与我们项目的关系

路线 B 的近期系统化版本。我们的结论不是"委派一定错"，而是"**工具必须有证据、能枚举实例**"；VipAct 正好代表"工具足够好时委派可以工作"的那一端。报告里用它平衡叙述：B 不是稻草人，而是一条有条件的路线。


### 进一步理解：它和 HuggingGPT 的差别

HuggingGPT 是"一个 LLM 调多个模型"；VipAct 更像"一个 orchestrator 协调多个 agent，每个 agent 再调专家模型"。差别不只是数量：

- 分工更细：不同 agent 负责不同子任务，避免一个上下文里塞进所有工具描述；
- 专家模型更专：像素级感知交给视觉专家，而不是通用模型；
- 规划更显式：orchestrator 先分析任务需求，再决定派谁去。

这也意味着工程复杂度更高：agent 之间的通信、工具选择、结果汇总都会引入新的失败模式。论文的消融与错误分析正是在量化这些设计选择的收益与代价。

### 在报告里怎么写

- 用它说明"路线 B 不是过时想法"：在工具有效、任务可拆时，委派 + 多 agent 仍然能打。
- 同时写清前提：我们的实验里 B 失败，不是因为"委派这个范式错了"，而是因为工具没有证据/词表覆盖不了。


### 答辩时可能被问

- **"多 agent 一定比单 agent 好吗？"** 不一定；它换来更细的分工，也带来通信成本与新的失败模式，论文用消融与错误分析来量化。
- **"这和路线 B 的失败矛盾吗？"** 不矛盾：VipAct 的前提是专家模型能提供有效感知；我们的实验里工具经常没有证据（空证据率），前提不成立。

### 读原文重点

orchestrator 与专家 agent 的分工、工具清单、以及错误分析里哪些失败是工具造成的。

## 5. Set-of-Mark：Set-of-Mark Prompting

**出处**：Yang 等，2023，arXiv:2310.11441（Microsoft）。【摘要，2026-10-15 已核】

### 一句话

不改模型，只改输入：先用分割模型把图切成区域并编号，再让 GPT-4V 对编号做指代与定位。

### 问题：Grounding 难在"输出坐标"

GPT-4V 的视觉 grounding（指代、定位）能力有限；能不能不训练模型，只通过输入形式把这项能力"逼"出来？这是一个很"工程"的问题：如果模型不擅长回归精确坐标，那就把坐标问题变成**选择题**。当时的交互式分割模型（SEEM / SAM）已经能给出质量不错的区域候选，缺的是"让 VLM 用上这些候选"的接口。

### 方法：分割 → 编号 → 提示

1. 用现成的交互式分割模型（SEEM / SAM）把图切成不同粒度的区域；
2. 在每个区域上叠加**标记**：字母数字编号、掩码、或框；
3. 把带标记的图交给 GPT-4V，让它对编号做指代、定位与推理。

核心洞察：**把"回归坐标"变成"选编号"**。模型不需要精确输出坐标，只需要在候选里指认；定位的精度由分割模型负责，语义判断由 VLM 负责。这也是"路线 C"的基本分工。标记形式（数字、字母、掩码、框）和粒度会显著影响效果，论文对此做了比较。

### 结果【摘要】

在零样本设定下，GPT-4V + SoM 在 RefCOCOg 上**超过了全量微调的 SOTA** 指代理解与分割模型。这条结果之所以引人注意，是因为它没有训练任何参数。

### 局限与注意

- 效果依赖分割质量：分割漏了、框错了，编号再清楚也没用；
- 标记密度与图的大小会互相制约；
- 它改善的是**指代/定位**，不直接解决计数、枚举与开放词表；
- "零样本超过全量微调"有具体任务与协议，报告里要写清楚是 RefCOCOg，不要泛化成"全面超过"。
- 分割模型本身是专用 CV 模型；如果分割失败，路线 C 就退化成"原图 + 噪声编号"。

### 与我们项目的关系

路线 C 的奠基作，也是我们 `annotate_objects` 的直接依据：工具负责"定位与编号"，主模型负责"语义推理"。真实工况里照片上 hybrid 82% 高于 direct 64%，和"标注把候选框出来、模型不必自己找"一致。基准上 hybrid 没有显著超过 direct，说明**编号不是万能的**：计数与细粒度识别仍然难。


### 进一步理解：为什么"选编号"比"回归坐标"容易

让 VLM 直接输出边界框，本质上是回归任务：它要给出四个连续坐标，误差一点就算错。SoM 把这件事拆成两步：

1. 分割模型负责"候选区域在哪"——这是专用 CV 擅长的；
2. VLM 负责"哪个编号对应哪个语义"——这是语言模型擅长的分类/指认。

这样一来，VLM 不需要精确回归坐标，只需要在有限候选里选一个；定位精度由分割模型保证，语义判断由 VLM 保证。**这是路线 C 的核心分工，也是它有效的原因。**

### 在报告里怎么写

- 用来解释路线 C 的操作定义："工具出候选并编号，主模型对编号做语义推理"。
- 不要写"SoM 解决了视觉定位"；写"SoM 在 RefCOCOg 的零样本设定下超过了全量微调的 SOTA"。


### 答辩时可能被问

- **"分割错了怎么办？"** 路线 C 会退化：编号本身不能纠正分割错误，错误会传给主模型。
- **"为什么零样本能超过全量微调？"** 因为任务被拆成了"候选生成 + 编号指认"，VLM 不需要学坐标回归，只需要做它擅长的语义选择。

### 读原文重点

标记的粒度与形式、分割模型的选择、零样本与微调的比较条件。

## 6. Graph-of-Mark：Promote Spatial Reasoning with Graph-Based Visual Prompting

**出处**：Frisoni 等，AAAI 2026，arXiv:2603.06663；正式版 AAAI 2026, Vol. 40, No. 36, pp. 30726–30734。【摘要】

### 一句话

SoM 的升级：不只给对象编号，还把对象之间的**关系**画成场景图叠在图上，专门补空间推理。

### 问题：编号把对象当成孤立的

SoM 把标注对象当作彼此孤立的实体，没有捕捉它们之间的关系；而"谁在谁左边、谁连着谁"这类空间推理，恰恰需要关系。作者认为，只给对象打标，等于把图变成"对象清单"，丢掉了结构。这个批评对路线 C 很关键：编号能帮模型定位，但不等于帮模型理解关系。

### 方法：场景图叠加

- 把**场景图**直接叠加到输入图像上（training-free），在图上标出对象及其关系；
- 同时在文本提示里加入辅助的图描述；
- 在 3 个开源多模态模型、4 个数据集上做零样本评测，并对"画哪些组件"做消融。

和 SoM 一样，它不改模型，只改输入；区别是输入里多了**边**（关系），不只是**点**（对象）。论文称它是"首个像素级、叠加场景图的视觉提示技术"（摘要原话大意），这个"首个"是作者 self-claim，引用时注意措辞。

### 结果【摘要】

- 零样本下，模型对对象位置与相对方向的理解稳定提升；
- 视觉问答与定位的基线准确率**最多提升 11 个百分点**；
- 正式版页码与卷期已在 Comments 里确认。

### 局限与注意

- 只测了 3 个开源模型、4 个数据集，不能直接外推到所有 VLM；
- 场景图从哪来、关系抽得准不准，决定了上限；
- 它是 training-free 的输入改造，不是新模型；引用时说"提示方式"而不是"模型能力"。
- 关系图可能引入新的噪声：画错一条边，模型可能被误导。
- "最多提升 11 个百分点"是某个数据集/模型上的最大值，不是平均值；报告里不要写成"普遍提升 11 点"。

### 与我们项目的关系

路线 C 的近期扩展：从"编号"走到"编号 + 关系"。我们的 hybrid 目前只做编号，没有关系图；如果以后要在空间关系题上继续压榨路线 C，这是可以直接试的方向。真实工况里，空间关系不是我们的主要分层，所以这条线暂时没有直接数据。


### 进一步理解：关系图的收益与代价

编号给的是"点"，关系图给的是"边"。对空间推理（谁在谁左边、谁连着谁），边比点更直接；但边也更容易画错：对象检测错一个、关系判断错一条，模型就会被引导到错误的结构上。所以 GoM 的收益是"在空间任务上稳定提升"，代价是"依赖场景图的质量"。

它是 training-free 的，意味着不用训练就能试；但也意味着它的上限受限于上游的检测/关系抽取模型——这又回到我们实验的核心结论：**工具的能力边界决定路线的上限**。

### 在报告里怎么写

- 用来展望路线 C："从编号到关系图，是 C 的一个自然扩展"。
- 不要把它写成"我们实验的一部分"——我们只做了编号，没有做关系图。


### 答辩时可能被问

- **"关系图从哪来？"** 来自上游的场景图/关系抽取；它的质量决定 GoM 的上限。
- **"为什么只测开源模型？"** 摘要只报告了 3 个开源 MLM、4 个数据集；闭源模型的结果不在摘要里，不能替它宣称。

### 读原文重点

场景图怎么画、关系从哪来、11 个点是哪个数据集/哪个模型上的。

## 附：如果 A 路线用 Counting to Four 而不是 ViT

**出处**：Le Dinh Anh 等，CVPRW 2026，arXiv:2604.10039。【摘要，2026-10-18 已核】

一句话：VLM 连"数到四"都做不好；作者用行为与机制分析指出，计数失败**同时**来自视觉感知上限与语言阶段对视觉证据利用不足，并提出一个轻量干预（Modality Attention Share, MAS），在生成答案时保证最低限度的视觉注意力。

与我们项目的关系：它直接解释了我们的第四轮——开思考后，能看见图的路线 counting 33%→60%，只拿到文本的委派 3%→3%。**后一半（语言阶段没用上视觉证据）是思考预算能改善的；前一半（编码器丢信息）不能。**

如果报告里 A 路线要强调"计数"，用这一篇比 ViT 更贴题；如果要强调"架构起点"，用 ViT。

## 补充：Qwen2.5-VL —— "VLM 很强"的正面证据

**出处**：Qwen 团队，2025，arXiv:2502.13923（Technical Report）。【摘要，2026-10-18 已核】

### 一句话

新一代通用 VLM 在**文档解析、表格/发票结构化抽取、图表与版面理解**上达到 SOTA 水平，旗舰 72B 在文档/图表任务上对标 GPT-4o 与 Claude 3.5 Sonnet。

### 问题：VLM 到底强在哪

MMVP 那一类工作说明 VLM 的"原子感知"有短板；但如果只引这一类文献，会得出"VLM 很弱"的片面印象。实际使用中，VLM 在**真实文档、截图、图表**上往往比"专用 OCR + 规则"更好用——因为它不只读字，还理解版面与语义。这篇技术报告就是这条正面证据。

### 方法（摘要口径）

- **动态分辨率**：按原图尺寸处理，而不是统一缩放到固定大小；原生动态分辨率 ViT + Window Attention，降低高分辨率图的计算开销。
- **绝对时间编码**：处理长视频时用绝对时间而非归一化位置，支持小时级视频与秒级事件定位。
- **能力面**：视觉识别、精确目标定位（框/点）、文档解析、发票/表单/表格的结构化抽取、图表/示意图/版面分析。
- **交互式视觉代理**：能推理、用工具、在电脑/手机界面执行任务。

### 结果【摘要】

- 旗舰 Qwen2.5-VL-72B **对标 GPT-4o 与 Claude 3.5 Sonnet**，尤其在文档与图表理解上突出；
- 提供三个尺寸，覆盖端侧到高性能场景；
- 摘要没有给出逐项基准数字；引用具体分数前需回原文。

### 与我们的数据怎么对上

- 真实工况：direct 总体 **83%**、文字截图 **92%**——这正是"通用 VLM 在真实截图/文档上很强"的现场证据；
- 委派：delegated 文字截图 **80%**、总体 **48%**——专用 OCR 并不比通用 VLM 更好；
- 基准：PerceptionBench 上 direct 只有 53%（counting 60%）——**原子感知仍然难**。

两边的结论不矛盾：**VLM 在"真实、语义完整、有版面"的图上很强；在"原子感知、答案唯一、刻意构造"的题上仍有短板。** 报告里要把这两面都写出来，才不会被问"到底强还是弱"。

### 局限与注意

- 这是**技术报告**，不是同行评审论文；引用时写"技术报告"；
- "对标 GPT-4o/Claude 3.5"是作者自报，具体基准与协议需回原文；
- 它强在文档/图表/界面，不等于"所有视觉任务都强"；
- 2025 年的模型，报告里不要写成"当前最强"。

### 在报告里怎么写

- Results 里加一句："通用 VLM 在真实截图上的表现（direct 92%）与 Qwen2.5-VL 报告的文档/图表能力一致"；
- Discussion 里用它平衡 MMVP：**编码器有短板，不等于 VLM 在真实工况下不强**。

### 答辩时可能被问

- **"Qwen2.5-VL 强，和你们的 DeepSeek V4.1-Flash 有什么关系？"** 它是"通用 VLM 这一类"的正面证据，不是我们模型的成绩；我们的成绩来自自己的 120 题与 60 图实验。
- **"那为什么 PerceptionBench 只有 53%？"** 因为那是原子感知基准，考的是"数兔子、读小字"这类题；Qwen2.5-VL 的强项是文档/图表/版面，不是同一类任务。
